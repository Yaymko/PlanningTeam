# Team Load App — еженедельное планирование загрузки команды

Веб-приложение (Streamlit) для встречи-планирования: загружаете еженедельный экспорт
тикетов с Agile-доски (.xlsx), прямо в браузере вписываете часы по каждому тикету на
исполнителя, видите дашборд с загрузкой по неделям и перегрузами, в конце выгружаете
готовый Excel с формулами и графиками для архива.

## Что нужно для запуска

- Python 3.9+ (проверялось на 3.11–3.13)
- Windows / macOS / Linux — без разницы, зависимостей от ОС нет

## Разворачивание — Windows

1. Установите Python, если его ещё нет: https://www.python.org/downloads/
   При установке отметьте галочку **Add python.exe to PATH**.
2. Склонируйте репозиторий или скачайте архивом и распакуйте.
3. Откройте папку проекта и дважды кликните `run.bat`.
   Скрипт сам поставит зависимости (при первом запуске) и откроет приложение в браузере
   на `http://localhost:8501`.

Если `run.bat` ругается, что `python` не найден — установите Python и перезапустите
терминал/проводник, чтобы подхватился обновлённый PATH.

## Разворачивание — вручную (Windows / macOS / Linux)

```bash
# 1. Клонировать репозиторий
git clone <URL_РЕПОЗИТОРИЯ>
cd team_load_app

# 2. (рекомендуется) создать виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Запустить приложение
streamlit run app.py
```

После запуска приложение откроется в браузере автоматически
(`http://localhost:8501`). Если не открылось — перейдите по ссылке из терминала вручную.

Остановить приложение — `Ctrl+C` в терминале, где оно запущено.

## Как пользоваться

1. **Загрузите файл** — еженедельный экспорт тикетов с Agile-доски (.xlsx). Приложение
   ждёт файл со структурой: листы «Обзор тикетов …» (справочно) + отдельный лист на
   каждого исполнителя с колонками `Тикет / Название / Колонка / Доска / Срок / В работе`
   и несколькими колонками-неделями вида `28.09–04.10 ч`.
2. **Вкладка «Ввод часов»** — выберите исполнителя, впишите часы по тикетам на нужную
   неделю. Строки «Доп. работа» — для задач, которых нет на доске: впишите название и
   часы. Новые строки можно добавлять кнопкой «+» внизу таблицы, лишние — удалять
   иконкой корзины. Там же задаётся норма часов в неделю на человека (по умолчанию 40).
3. **Вкладка «Дашборд»** — сводная таблица по команде с подсветкой перегруза (красный —
   выше нормы, зелёный — в пределах), график загрузки по людям и неделям, график
   «команда план vs норма», список перегруженных.
4. **Экспорт** — кнопка «Сформировать Excel» внизу собирает файл с формулами, той же
   сводкой и графиками — для архива или отправки тем, у кого нет доступа к приложению.

Недельные колонки читаются из заголовков файла динамически — при новой выгрузке с
другими датами ничего пересобирать не нужно, просто загрузите новый файл.

## Структура проекта

```
team_load_app/
├── app.py                      # UI: Streamlit-страницы, дашборд, вкладки
├── core.py                     # чистая логика без Streamlit: разбор файла, сборка Excel-экспорта
├── tests/                      # unit- и smoke-тесты (pytest)
├── requirements.txt            # зависимости приложения
├── requirements-dev.txt        # + зависимости для разработки (pytest, ruff)
├── pyproject.toml              # конфиг ruff
├── .github/workflows/ci.yml    # CI: линт + тесты на каждый push/PR
├── run.bat                     # быстрый запуск на Windows (ставит зависимости и стартует)
└── README.md
```

## Разработка и CI

Логика разбора файла и сборки Excel-экспорта вынесена в `core.py` отдельно от
Streamlit-интерфейса в `app.py` — это позволяет тестировать её напрямую, без запуска
веб-сервера.

Локально, перед коммитом:

```bash
pip install -r requirements-dev.txt
ruff check .          # линт
pytest -q             # unit-тесты core.py + smoke-тест запуска app.py
```

На GitHub настроен workflow `.github/workflows/ci.yml` — при каждом push и pull request
в `main` он на Python 3.11 и 3.12 прогоняет линт (`ruff`), проверку компиляции и тесты.
Если какой-то шаг падает — PR будет помечен красным, это сигнал не мёржить, пока не
починено.

## Данные

Загружаемые `.xlsx`-файлы и сформированные экспорты не попадают в репозиторий
(исключены через `.gitignore`) — в них реальные данные по сотрудникам и тикетам.
